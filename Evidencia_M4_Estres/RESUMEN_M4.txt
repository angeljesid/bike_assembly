PUNTO DE QUIEBRE: ~60-66 usuarios concurrentes
- 0-66 usuarios  (0-20s) : ~95-100% de exito
- >66 usuarios   (20s+)  : exito cae a <15% (colapso)
- Causa: agotamiento del pool de conexiones HikariCP (default 10)
- El servidor rechaza conexiones (HttpHostConnectException)

CPU del servidor (en vivo durante el estres):
- Max 62.5%, prom 10.6%  -> NO es el cuello de botella
- El limite real es la conexion a la BD (HikariCP pool=10)

RECUPERACION:
- App responde 200 tras la prueba (no requiere reinicio)
- 6 usuarios intactos y activos; la carga solo hizo GET, no modifico datos

RECOMENDACION:
- spring.datasource.hikari.maximum-pool-size >= 50
- server.tomcat.max-threads >= 200
Con eso el punto de quiebre se moveria mucho mas arriba.
